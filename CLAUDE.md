# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A thin Python CLI wrapper around [Packer](https://packer.io) for building OpenStack (Glance) images in
[NREC](https://www.nrec.no). It exists so users don't have to write Packer templates: it creates the
throwaway OpenStack resources Packer needs, invokes `packer build` against a bundled template, and
cleans up afterwards.

This fork's `origin` is `trondham/imagebuilder`; `upstream` is `norcams/imagebuilder`.

## Commands

```bash
# Lint — this is what CI runs (.github/workflows/python-package.yml), matrix py3.9/3.10/3.11
ruff check --select=E9,F63,F7,F82 --target-version=py39 .
ruff check --target-version=py39 .

# Tests — CI runs these too; ruff is pinned to 0.15.22 and pytest to 8.4.2
pytest -q
pytest tests/test_main_flow.py -q          # a single file
pytest -k "cleanup" -q                     # a single case

# Dev install (see DEVELOPMENT.md)
python3 -m venv . && source bin/activate
pip install -r requirements.txt
pip install -e .

# Run without installing
./imagebuilder <command>          # wrapper around image_builder.imagebuilder:main
```

Tests live in `tests/` and use stand-in OpenStack clients (`tests/conftest.py`) plus a fake HTTP
layer, so they need no credentials and touch no network. `test_main_flow.py` drives `main()` itself
with a fake `BuildFunctions` — that is where the cleanup-on-failure guarantees are pinned down.

Packaging metadata and the console script live in `pyproject.toml`; there is no `setup.py`.

Running any command requires OpenStack credentials in the environment (`source keystone_rc.sh`) —
`get_openstack_rc()` reads `OS_USERNAME`, `OS_PROJECT_NAME`, `OS_PASSWORD`, `OS_AUTH_URL`,
`OS_IDENTITY_API_VERSION`, `OS_USER_DOMAIN_NAME`, `OS_PROJECT_DOMAIN_NAME`, `OS_REGION_NAME`,
`OS_NO_CACHE` and exits if any are missing (`OS_CACERT` is optional). `packer`, `ssh-keygen`,
`openssl`, and the `glance` CLI must be on `$PATH` — on RHEL/CentOS beware the unrelated
`/usr/sbin/packer`; `/usr/bin/packer` is the right one.

## Architecture

`image_builder/imagebuilder.py:main()` is a straight-line procedural driver — all orchestration lives
there, and the other modules are stateless-ish helper classes. Two subcommands, dispatched by
`parsecommands.Commands` (which uses the argparse "git-style subcommand" pattern: `sys.argv[1:2]`
selects the method, `sys.argv[2:]` is parsed by that method's own parser, and `build_args` /
`bootstrap_args` are `False` when unused).

**`build`** (`build.py:BuildFunctions`) — the core flow, in order:
1. `helpers.make_tmp_dir()` — a `tempfile.mkdtemp(prefix='imagebuilder-')` holding the SSH keypair and
   Packer's manifest; everything in the flow is scoped to it.
2. `find_template()` — locates `template.pkr.hcl` in `template_dir`.
3. `find_network_id()` — resolves the network name (default `Dualstack`) to an id via openstacksdk.
4. `run_packer_init()` — `packer init`, which installs the openstack plugin.

   Steps 2–4 deliberately run *before* anything is created in OpenStack: each can fail on bad user
   input, and failing here costs nothing to clean up.
5. `create_security_group()` / `create_keypairs()` — temporary OpenStack resources named
   `imagebuilder-<uuid4hex>`, allowing SSH ingress on v4 and v6. The keypair is generated by shelling
   out to `ssh-keygen`.
6. `run_packer()` — builds a `packer build -var k=v ...` argv and streams stdout through
   `helpers.log_subprocess_output` into `logging`.
7. `parse_manifest()` — Packer's `manifest` post-processor writes `packer-manifest.json` into the temp
   dir; `builds[0].artifact_id` is the resulting Glance image id. This is the only channel by which the
   build result comes back from Packer.
8. Optional `download_image()` (via `conn.image.download_image`, then **deletes the image from
   Glance**), optional `--purge-source`, then `cleanup()` + `clean_tmp_files()`.

One openstacksdk `Connection` covers everything: `conn.compute` (keypairs), `conn.network` (security
groups, networks), `conn.image` (image create, download, delete). novaclient and glanceclient were
dropped once the last calls moved over. Note `self.conn` holds the connection rather than a proxy
such as `conn.network`, because touching
a proxy authenticates and discovers endpoints — the constructor is deliberately free of network
traffic.

Everything after the first OpenStack resource is created runs under a `try/finally`, so `cleanup()` is
reached on exceptions and on Ctrl-C (SIGINT becomes `KeyboardInterrupt`, which unwinds). `cleanup()` is
written for that position: it skips ids that are `None` and swallows API errors, because raising there
would mask the original failure. SIGTERM and SIGKILL still bypass it — verified — so those remain the
one case that orphans `imagebuilder-*` resources.

**`bootstrap`** (`bootstrap.py:BootstrapFunctions`) — downloads a cloud image from a URL, optionally
verifies it against a checksum file (substring match of the computed hexdigest in the fetched file), and
uploads it to Glance with hardware properties set from the flags (`hw_disk_bus=scsi` +
`hw_scsi_model=virtio-scsi` unless `-s`, `hw_firmware_type=uefi` + `hw_machine_type=q35` with `-e`,
always `hw_rng_model=virtio`). On success it writes the bare image id to **stdout** and nothing else —
all other output goes to `logging` — so `bootstrap ... | xargs -I % imagebuilder build -s % ...` works.

**Config** (`config.py`) — `configparser` over `./config`, `~/.imagebuilder/config`,
`/etc/imagebuilder/config` (later files win). Only `[main] template_dir` and `download_dir` are read,
and `IB_TEMPLATE_DIR` / `IB_DOWNLOAD_DIR` override them.

### Packer template and provision scripts

`template.pkr.hcl` (HCL2) is a *file*, not a directory — `find_template()` looks for it in
`template_dir`, falling back to a legacy JSON template named `template` if that's all it finds (in
which case `packer init` is skipped and the openstack plugin must be installed by hand). Its
`provisioner "shell"` `scripts` list is a fixed pipeline of `scripts/*.sh` with `var.provision_script`
(the user's `-p` script, default `/bin/true`) slotted in near the end, before the cleanup scripts.
Adding a stage to every build means editing this list. Paths there use `${path.root}` — the directory
holding the template — so builds don't depend on Packer's working directory.

Packer stopped bundling builder plugins in 1.10, so `packer init` must run before `packer build`; the
`required_plugins` block pins `github.com/hashicorp/openstack`. `required_plugins` is HCL2-only, which
is why the JSON template had to go.

Scripts under `scripts/` run on the builder VM as the cloud-init user via `sudo`, across a wide range of
guests (RHEL 8/9/10, Alma, CentOS Stream, Fedora, Debian, Ubuntu). They share a copy-pasted
Omnitruck-style platform-detection preamble that sets `platform` (`el`/`fedora`/`debian`/`ubuntu`) and
`major_version`; keep that convention when adding one. A script that doesn't apply to the detected
platform prints a message and `exit 0` — it must not fail the build. Note `grub.sh`, `nvidia-grid-driver.sh`,
and `uib-puppet.sh` are not in the default template's list; they are opt-in, used as the `-p` script or
by site-specific templates.

`nvidia-grid-driver.sh` pulls the vGPU guest driver and per-region licensing tokens from
`download.iaas.uio.no` and selects the BGO/OSL `gridd.conf` by grepping `/run/cloud-init/` for the
availability zone. Recent history is mostly churn here (pinning/unpinning driver versions, refreshing
client tokens) — check `git log -- scripts/nvidia-grid-driver.sh` before changing it.

`example/` is a self-contained smoke-test setup (its own `config`, a trimmed `template`, a trivial
`provision.sh`, and Terraform to boot the resulting image); use it to sanity-check changes end to end.

## Conventions

- Commit messages follow Conventional Commits (`feat:`, `fix:`) for functional changes; script tweaks
  are often plain imperative one-liners.
- `pyproject.toml` disables ruff `E501` (line length) and `E722` (bare `except`) — bare excepts are used
  deliberately throughout and should not be "fixed" as drive-by cleanup.
- New Python code targets 3.9 (CI's floor).
